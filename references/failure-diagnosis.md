# 失败诊断：先分清变换、蒙皮、网格、IK、动画和视口

## 1. 诊断原则

按以下顺序排查，不要从最显眼的现象直接跳到修网格：

```text
原始模型是否干净
→ 骨架与网格父级是否保持原样
→ 局部中立变换是否被覆盖
→ 世界空间姿态是否正确
→ 蒙皮和辅助变形结构是否能承受目标动作
→ IK/约束是否真的驱动末端
→ 动画是否破坏基准
→ 视口和渲染是否显示了正确的对象与相机
```

跳过前一层会让后一层的“修复”变成掩盖。

## 2. 症状与证据对照

| 症状 | 优先检查 | 不要直接做什么 |
|---|---|---|
| 身体向前扭，但 Spine 局部角很小 | 父级世界矩阵、Spine/Head 世界位置 | 猜一个新的 Spine.rotateX |
| 人物整体躺下或比例突然放大 | arm/mesh 的旋转、scale、父级是否不一致 | 手动缩放 mesh 到“看起来差不多” |
| 手肘或膝盖不弯 | 骨链中间关节、twist 骨、IK 末端与手柄位置 | 继续移动 IK 手柄 |
| 大角度弯臂袖口翻开 | SDEF、分层袖壳、权重、扭转骨 | 加 Delta Mush 后宣称根治 |
| Maya 导入新模型卡死 | morph 网格数量、总顶点数、内存 | 重复导入同一个完整 FBX |
| 动画后姿态突然扭曲 | 是否清零了非零中立旋转、是否覆盖落座补偿 | 给所有关节再打一个零值键 |
| 每个镜头画面相同 | 相机实际名称、可见面板、lookThru、图像哈希 | 只统计相机数量 |
| 脚本成功但场景没变化 | 业务日志、实际节点名、保存后回读 | 把 poller 的 ok:true 当作业务通过 |

## 3. 局部角度不等于世界姿态

真实案例中，马县长的数据曾出现：

- `Spine` 局部 `rotateX = 1.5°`。
- 同一关节世界旋转约 `42.29°`。
- 另一诊断场景中局部为 `6°`，世界旋转约 `46.6°`。
- 从脊椎到头的上升量和水平前移量接近，躯干实际前倾约 45°。

结论：只修改局部 X 无法说明身体是否直立。必须读取：

```python
spine_pos = cmds.xform(spine, q=True, ws=True, t=True)
head_pos = cmds.xform(head, q=True, ws=True, t=True)
spine_world_matrix = cmds.xform(spine, q=True, ws=True, m=True)
```

再用世界向量计算躯干相对竖直方向的夹角。可调用：

```python
from maya_pose_tools import torso_angle_from_up
angle = torso_angle_from_up("Bip001Spine", "Bip001Head")
```

## 4. 为什么“恢复零旋转”经常失败

FBX/MMD 转换后的骨骼可能有：

- 非零 `Root`、`Center`、`Groove`、`Bone` 旋转。
- 非零 `Spine`、`Neck`、`Head` 中立旋转。
- 用于坐标系转换的 `-90°` 父级旋转。
- 用于单位转换的 `×100` 父级缩放。
- 左右镜像和不同 rotateOrder。

把关节全部设为零会破坏转换链，而不是恢复直立。正确做法是从**同一模型的原始 FBX 或干净场景**读取中立局部变换，并保留合法的父级转换。

## 5. 骨架坏了还是蒙皮坏了

将两类问题分开：

### 姿态算法问题

- 局部角被误读为世界角。
- 上游关节已有旋转，后续脚本继续叠加。
- 两段腿被拆成两个单段 IK。
- 骨骼目标只凭固定角度猜测。
- 动画每镜重新读取“当前值”，导致误差逐层累积。

### 蒙皮/网格结构问题

- 旧 MMD 模型的 SDEF 辅助结构在转换后不能承受大角度弯臂。
- 袖口和手臂是分层壳，弯曲时互相翻开。
- 手指或扭转骨被误当成主肘关节。
- 网格被重新父级化、缩放或旋转后与骨架坐标系分离。

姿态错误不能全怪模型，袖口破裂也不能全怪姿态算法。分别验证、分别报告。

## 6. IK 手柄到了，人物没到

真实案例中曾出现：

- IK 手柄世界位置精确等于目标。
- 末端脚踝仍停在旧位置。
- 中间关节几乎不弯曲。
- 骨骼没有旋转锁定，但求解结果仍不符合目标。

因此必须同时记录：

```text
handle_position
requested_target
actual_end_position
actual_middle_position
start/middle/end local rotations
incoming rotate connections
```

只记录手柄位置是假证据。若求解器在这套导入骨链上不稳定，改用显式中间关节的解析两段 IK，并用实际末端位置验收。

## 7. 模型数据量与内存

真实新模型的参考数据：

- 身体网格约 28,575 顶点。
- 242 根骨骼。
- 完整文件带约 149 份表情 morph。
- 合计约 426 万顶点。
- 在约 8GB 内存的机器上，完整导入曾导致卡顿和崩溃。

正确做法是先验证并保存清理副本，再在工作场景中使用该副本。不要每轮修复都重新导入完整 morph 数据。

## 8. 视口证据也可能是错的

真实项目中出现过：

- 71 台相机只有 12 种不同位置/朝向。
- 图片文件名不同，但哈希完全相同。
- 相机创建后实际名称带后缀，脚本仍使用原名称。
- 只设置 `modelEditor(camera=...)`，画面仍来自旧视口。
- 保存后重开才发现观察相机没有按预期存在。

诊断视口时：

1. 查询可见 `modelPanel`。
2. 使用相机创建返回值。
3. 执行 `lookThru(panel, actual_camera)`。
4. 查询面板当前相机。
5. 渲染后比较图像哈希并目视。
6. 保存、重开、再拍一张核对。

## 9. 最小诊断输出

使用：

```python
from inspect_character_scene import inspect_scene

report = inspect_scene(

```

根据报告选择修复路径。不要在证据不全时直接运行“最终修复脚本”。
