# 姿态修复后的动画、相机和渲染安全

## 1. 先锁定已验收基准

1. 保存当前头部、手臂和腿部基准旋转与世界矩阵。
2. 保存人物组的落座补偿，不要归零。
3. 确认当前动画曲线、约束和 IK 数量。
4. 另存动画工作版本，不覆盖姿态基线。
5. 明确允许和禁止的身体部位。

“当前没有动画曲线”意味着可以从基准设计动作，不意味着可以把所有关节设为 0。

## 2. 头部动作

### 2.1 由视线目标驱动

为每次转头确定目标：另一人物、桌面、杯子、镜头外位置或正前方。使用世界目标计算头部旋转，避免套用固定 `Head.rotateY`。

### 2.2 按剧情设置节奏

- 转头前有短暂停顿。
- 到达目标后保持一小段。
- 视线转移要有先后，不要匀速来回。
- 不要给所有镜头使用相同的首中尾三键模板。
- 不要以 root 摇摆代替头部表演。

### 2.3 检查姿态副作用

转头后检查颈部、肩部、袖口和构图。若头部转动需要过大角度，优先调整机位或简化动作，不强行扭转颈部。

## 3. 手部动作

- 以当前手掌姿态为基准。
- 显式使用 UpperArm / Forearm / Hand 或对应旧模型骨名。
- 不将 ArmTwist / HandTwist 当成肘部主关节。
- 大角度动作后检查肩、肘、腕和袖口。
- 手指是否需要动画由用户决定；不要默认逐指弯曲。
- 指向动作可以保持现有手型，不必为“指”单独做手指动画。

旧 MMD 模型如果在大角度弯曲时破袖，优先减少动作，必要时只保留头部表演。

## 4. 不擅自扩大动作范围

如果用户只允许头部和手部：

- 不制作站起、坐回、腿部重新运动。
- 不制作大幅 Spine 前倾。
- 不用 root 移动模拟身体动作。
- 对分镜中的站起/前倾描述，用头部、手部和相机表达，或向用户确认扩大范围。

只有确认后才增加身体和腿部动画。

## 5. 道具和手部绑定

在拿杯、碰杯、倒酒、敲瓶前检查：

1. 场景里实际有几个杯子、瓶子、碗和筷子。
2. 道具是否已经有约束或动画。
3. 手掌接触点和道具重心是否合理。
4. 手指不动时，现有手型能否容纳道具。
5. 道具放下后是否接触桌面。
6. 切镜前后道具是否突然跳回。

若需要复制道具，记录新增节点并出静帧确认。使用保持世界位置的绑定方式，绑定后检查手与道具的相对位置。不要只移动手腕而让杯子静止，却报告“拿杯完成”。

## 6. 相机设计必须读取剧情关系

每镜至少记录：

```text
镜号、首尾帧、景别、画面主体、说话者、听者
前景人物及左右位置、视线目标、手部动作
相机起止位置、起止瞄准点、焦距、所用关系轴
原片参考帧、验收状态
```

不要只按“动作文本中第一个人名”判断说话者；镜头外台词和反应镜头很常见。

## 7. 180° 轴线和前后景

- 为每对对话者建立关系轴。
- 保持正反打在同一侧，除非原片明确越轴。
- 检查相邻镜头中人物视线方向是否匹配。
- 前景头/肩必须真正进入画面，不得只写在设计文档中。
- 相机不能穿墙、穿桌或穿人物。
- 不为了“71 镜都不同”而制造无意义机位；重复必须有原片依据，不得偷懒重复。

## 8. 运镜

- 起点关键帧放在该镜首帧，终点放在尾帧。
- 起止位置和瞄准点必须有真实变化。
- 按相机自身方向解释“向左/向右”，不要固定修改世界 X。
- 很短镜头不做大幅绕弧。
- 区分上移、下移、跟随、手持晃动和定镜。
- 不使用随机扰动或统一正弦摆动冒充原片运镜。

## 9. 相机实际名称与视口切换

相机创建后可能自动带后缀。始终保存返回值：

```python
actual_camera = cmds.camera(name="DS_S003_CAM")[0]
camera_map["S003"] = actual_camera
```

渲染前：

```python
panels = cmds.getPanel(type="modelPanel") or []
visible = [p for p in panels if cmds.control(p, q=True, visible=True)]
panel = visible[0]
if not cmds.objExists(actual_camera):
    raise RuntimeError("Missing camera")
cmds.lookThru(panel, actual_camera)
```

仅设置 `modelEditor(camera=...)` 可能留下旧视口。出图后同时检查面板相机、图像哈希和真实内容。

## 10. playblast 与帧序列

- 使用 `clearCache=True`、`viewer=False`、`showOrnaments=False`。
- 预热帧不得混入正式序列。
- `frame=[f0, f1]` 是两帧列表，不是区间。
- 使用正确的 `startTime/endTime`，或显式 `frame=list(range(f0, f1+1))`。
- 每镜立即核对 `end-start+1` 的文件数。
- 文件名按数字帧号排序。
- 总帧数不符时查明原因，不得用切片截断多余帧来隐藏错误。
- 新渲染使用新目录，避免旧帧混入。

## 11. 帧率、字幕和音轨

- 动画前确认 Maya 时间单位；`film` 通常表示 24fps。
- 原片为 23.976fps 时，在打键前设置并查询确认。
- 图像序列编码使用 `-framerate 24000/1001`，不要沿用旧 24fps 脚本。
- 字幕在画面和剪辑确认后最后烧入。
- 改变分辨率时重新生成字幕，不直接拉伸低分辨率字幕。
- 原片音轨是否回贴由用户确认；启用后检查起始偏移和音画同步。
- 编码后同时检查帧数、帧率、宽高、时长、音频流和切点抽帧。

## 12. 动画验收顺序

```text
单关节短测试
→ 单人物关键姿态静帧
→ 三人正式近景
→ 相邻 5–6 镜短段
→ 道具和复杂动作专项短段
→ 用户确认
→ 分批完成全部镜头
→ 保存后回读
→ 用户确认后全片渲染
```

不要从“修好像一个关节”直接跳到“渲染 3512 帧”。
