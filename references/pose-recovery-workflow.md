# 人物姿态恢复完整流程

## 1. 保存现场并建立停止条件

1. 复制原始场景，另存新工作版本。
2. 保留原始 FBX、最近稳定基线和用户确认过的场景。
3. 明确本轮只做姿态、只做一个人物，还是包含动画。
4. 明确验收图、目标误差、穿插检查和需要用户确认的停止点。
5. 不在未验收时启动全片渲染。

## 2. 提取原始中立姿态

优先从同一人物的原始 FBX 新建干净场景，记录所有骨架节点的：

- `translate`。
- `rotate`。
- `scale`。
- `jointOrient`。
- 父级名称。
- 世界位置和世界矩阵。

将中立数据保存为 JSON，避免反复导入完整模型。恢复时按明确映射写回同名或同骨架节点，不要按列表顺序猜测对应关系。

### 注意

- 不要改变蒙皮网格父级。
- 不要给锁定通道强行解锁后写入；先判断锁定是否来自合法导入状态。
- 不要删除 SDEF 或辅助结构，除非已经证明它们不参与当前变形。
- 保留角色组中用于落座、地面或坐标转换的补偿；补偿值不是“脏数据”。

## 3. 恢复躯干、脖子和头

从原始中立数据恢复 `Spine / Spine1 / Neck / Head`，不要写死为 0。

然后读取世界位置，计算：

```text
躯干方向 = Head.world_position - Spine.world_position
躯干倾角 = 躯干方向与世界上方向的夹角
```

同时检查主网格包围盒和真实渲染。如果数值直立但网格仍扭曲，继续查蒙皮和父级，不要继续拧脊椎。

## 4. 用两段 IK 修腿部坐姿

显式确定：

```text
start  = 大腿/髋臼关节
middle = 膝盖关节
end    = 脚踝关节
```

不要把 `Foot` 的父级或 twist 骨自动当作膝盖；通过实际层级和名称确认后显式传入。

### 4.1 确定目标

- 先根据臀部网格与椅面确定髋关节高度，不要固定使用某个项目里的 54 或 58cm。
- 脚踝高度由原始站立模型的脚底与踝关节差值计算。
- 脚踝前后位置根据大腿长度、参考坐姿和桌椅位置确定。
- 膝盖极点放在身体前方，并略微向外，避免膝盖反向。

### 4.2 解析两段 IK 的几何

已知两段长度 `l1`、`l2`，起点 `S`，末端目标 `T`：

1. 计算目标距离并限制在可达范围内。
2. 求起点到目标的单位方向 `u`。
3. 将极点方向投影到垂直于 `u` 的平面，得到膝盖弯曲方向 `v`。
4. 计算：

```text
a = (l1² + d² - l2²) / (2d)
h = sqrt(l1² - a²)
K = S + u*a + v*h
```

`K` 即膝盖目标。然后分别对齐大腿和小腿，并读取脚踝实际位置。

### 4.3 Maya 行向量与四元数顺序

本项目实测必须：

```python
new_q = old_q * delta
```

不是：

```python
new_q = delta * old_q
```

左乘会让带旋转父级的角色偏向一侧。最小单位测试如果旧朝向为单位矩阵，两种顺序会假装都正确，因此必须在带非单位父级旋转的骨链上测试。

### 4.4 Maya 2024 API 兼容

本次环境实测可用：

```python
delta = om.MQuaternion(current_unit_vector, desired_unit_vector)
```

不要假定所有 Maya 版本都支持相同的 `setAxisAngle` 或 `inverted` 调用。先查当前 API，失败时用已验证的两向量构造和矩阵/约束路径。

### 4.5 写回世界旋转

使用临时 locator 和 `orientConstraint` 写回绝对世界朝向，让 Maya 处理父级缩放和坐标系。完成后删除临时约束和 locator，保留普通关节旋转。

如果关节已有动画或约束输入，先明确烘焙/解除策略；不要在未知连接上强行写值。

### 4.6 调用工具

```python
from maya_pose_tools import solve_two_bone_world

leg = solve_two_bone_world(
    start="Bip001LThigh",
    middle="Bip001LCalf",
    end="Bip001LFoot",
    target=[6.78, 10.10, -67.28],
    pole=[6.78, 62.00, -35.00],
    preserve_end_rotation=True,
    tolerance=0.01,
    raise_on_error=True,
)
```

返回结果包含目标是否被钳制、膝盖目标、实际膝盖、实际脚踝和误差。必须检查 `target_was_clamped`，避免把不可达目标误报为命中。

## 5. 保持脚底朝向

两段 IK 可能让脚踝继续继承小腿方向。求解前记录脚踝中立世界旋转，求解后恢复该世界旋转，再检查：

- 脚底是否贴地。
- 脚尖是否上翘或穿地。
- 鞋子是否异常拉伸。
- 左右脚是否交叉。

不要只检查踝骨位置。

## 6. 修手臂和袖口

### 6.1 旧 MMD 模型

- 优先自然垂放或小幅手部动作。
- 避免大角度弯臂和极端扭转。
- 检查 `ArmTwist`、`HandTwist` 与主 `ForeArm` 的层级。
- 如果袖壳仍破裂，简化动作或更换已验证模型；不要用 Delta Mush 掩盖。

### 6.2 新模型

- 先做同条件弯臂对比，再允许搭桌或指向。
- 手肘极点通常放在身体外侧。
- 手腕目标需要结合手掌厚度和桌面高度，而不是把腕关节中心放到桌面内部。
- 每次改变肩部高度、手腕前后距离或极点高度后，重新检查小臂是否穿桌。

真实案例中，抬高髋部后，即使手腕目标不变，小臂路径也会改变并产生新的桌面穿插。因此姿态修改不能只验收被改的那一段。

## 7. 碰撞与尺度检查

使用世界空间顶点和包围盒：

```python
from maya_pose_tools import (
    mesh_bounding_metrics,
    count_vertices_in_box,
    count_vertices_in_vertical_cylinder,
)

metrics = mesh_bounding_metrics("NH_MaleM_140_LOD0")
table_vertices = count_vertices_in_vertical_cylinder(
    "NH_MaleM_140_LOD0",
    center_x=0.0,
    center_z=0.0,
    radius=87.0,
    y_min=71.75,
    y_max=75.25,
)
```

碰撞顶点计数是报警信号，不是唯一判定：

- 桌体内部顶点通常是不应出现的穿插。
- 椅面附近的顶点可能包含合理接触，需要结合四视图判断。
- 目标误差为零不代表网格没有穿插。
- 包围盒正常不代表袖口没有翻折。

## 8. 保存、重开、重算

每轮修复：

1. 另存新版本。
2. 记录场景路径和文件大小。
3. 重新打开该版本。
4. 重算关节目标、躯干角度、网格包围盒和碰撞计数。
5. 重拍四视图并检查图像不重复。
6. 保留日志和剩余问题。

内存里正确但保存后丢失，不算完成。

## 9. 何时停止修模型

出现以下情况时，停止继续叠加修补并回到干净基线：

- 同一问题连续两轮仍靠猜角度修补。
- 骨架与网格的坐标系关系已被重新父级化破坏。
- 每修一个部位就引入更大的穿插或扭曲。
- 旧模型袖口在目标动作下反复破裂。
- 无法说明当前文件相对上一版具体改变了什么。

更换经过验证的模型或减少动作范围，通常比继续打补丁更可靠。
