# 真实案例：《让子弹飞》鸿门宴人物扭曲修复

## 1. 案例背景

项目中需要将三个人物模型放入 Maya 场景，完成围桌坐姿、后续头部/手部动作和 71 镜运镜。此前自动化流程出现了严重身体扭曲、手臂袖口破裂和重复机位。

本案例的价值不在于记住某套固定角度，而在于：**通过场景证据区分摆姿算法、蒙皮结构和视口缓存，再逐层修复。**

## 2. 初始证据

### 2.1 身体前扭

旧场景中曾读取到：

- `Spine` 局部 `rotateX=1.5°`，世界旋转却约 `42.29°`。
- 另一处诊断中局部 `6°`，世界旋转约 `46.6°`。
- 从脊椎到头上升约 34.3cm，同时向前约 35.6cm，躯干实际前倾约 46°。

结论：局部欧拉角被误当成世界前倾角，父级和上游姿态叠加是主因。

### 2.2 袖口破裂

旧 MMD 模型存在 `*_mmd_sdef_c`、`*_mmd_sdef_r0`、`*_mmd_sdef_r1`。同条件弯臂渲染显示：

- 旧模型袖子和手臂壳翻开、变黑、穿插。
- 新模型 `NH_MaleM_140` 能保持手臂完整。

结论：大角度弯臂破袖主要是旧模型蒙皮/分层结构问题，不能全归罪于骨架，也不能用 Delta Mush 根治。

### 2.3 新模型数据量

新模型：

- 身高约 160.8cm。
- 242 根骨骼，Bip001 命名。
- 身体网格 28,575 顶点、12 个材质。
- 完整文件约 149 份表情 morph，合计约 426 万顶点。

在约 8GB 内存的机器上，完整导入是卡顿和崩溃的重要原因。最终使用清理后的单身体网格场景，而不是每轮重新导入完整 FBX。

### 2.4 相机重复

旧 `v10_prod.mb` 有 71 台分镜相机，但按位置和朝向去重后只有 12 种；最大一组重复 18 次。根因是旧生成器只按主体、景别和左右移动计算机位，没有真正处理前景人物和镜头承接。

## 3. 修复采用的结构

### 黄四郎和师爷

- 从各自原始 FBX 提取并恢复中立局部变换。
- 保留合法父级转换和落座补偿。
- 恢复脊椎、脖子、头部中立状态。
- 用两段 IK 重新摆腿。
- 手臂自然放到腿侧，不安排大角度弯臂。

### 马县长

- 使用清理过 morph 的新模型。
- 保留 `Root / Bip001` 骨架。
- 蒙皮网格 `NH_MaleM_140_LOD0` 保持顶层，不改变父级。
- 使用 Bip001 的 Thigh/Calf/Foot 和 UpperArm/Forearm/Hand 显式骨链。
- 双手先做接近桌面的姿态，再检查实际网格。

## 4. 关键算法修正

### 4.1 自带 IK 没有产生可信结果

测试中 IK 手柄已经移动到目标，但末端仍停留在旧位置，中间关节没有正常弯曲。继续移动手柄不能解决问题。

改为解析两段 IK：由骨长、末端目标和极点计算膝盖/手肘位置，再写回两段世界旋转。

### 4.2 四元数乘法顺序

第一次解析求解使用了：

```python
new_q = delta * old_q
```

结果在带旋转父级的人物上严重偏向一侧。改为符合本项目 Maya 行向量约定的：

```python
new_q = old_q * delta
```

并使用临时世界朝向约束写回，脚踝和手腕才真正命中目标。

### 4.3 保存和图像证据也需要修复

生成观察相机时，后续脚本最初没有使用创建命令返回的实际名称，导致切换失败或重复旧视口。修复方式：

- 保存相机创建返回映射。
- 对可见面板执行 `lookThru(panel, actual_camera)`。
- 删除并重新生成目标验收图，避免旧文件混淆。
- 核对 16 张原图哈希均不同。
- 保存后重开场景，确认 16 台观察相机全部存在。

## 5. 迭代记录：哪些方向被否定

| 版本 | 实际结果 | 结论 |
|---|---|---|
| v1 | 自带 IK 末端误差可达约 19–33cm；脚底到地面以下；马县长有桌面内部顶点 | 不接受“手柄到了”的假证据 |
| v2 / v3 | 解析算法使用了错误的四元数左乘顺序，腿部和手臂严重偏离目标 | 否定左乘；不是继续调目标能解决的问题 |
| v4 | 改为右乘后，腿部和手部目标误差降到约 0.001cm 内，桌面内部顶点为 0 | 算法方向成立，但取景和椅面接触仍需修 |
| v5 | 髋部由 54cm 提到 58cm，旧人物和马的椅面接触减少；马县长出现 78 个桌面内部顶点 | 改变肩部高度会改变手臂穿插路径，必须重验全身 |
| v6 | 把手肘极点抬高后，马县长桌面内部顶点增加到 322 | 否定“极点越高越安全”的猜测 |
| v7 | 手腕目标收近桌沿，手肘极点降低并保持外侧；桌面内部顶点重新为 0 | 通过本轮姿态验收 |

不要把 v1–v6 当作后续工作起点。它们只证明哪些方向失败。

## 9. 可泛化与不可泛化

### 可泛化

- 先诊断变换层级，再修姿态。
- 从同一原始模型恢复中立数据。
- 世界空间解析两段 IK。
- 显式中间关节，排除 twist 骨误判。
- 右乘世界增量旋转，并在实际父级结构下测试。
- 末端实际位置、网格、四视图、保存后回读共同验收。
- 改身体高度后重新检查手臂和道具。

### 不可直接复制

- 具体关节名称和人物位置。
- 54/58cm 髋部高度。
- 桌面高度、脚踝目标和极点坐标。
- 具体局部欧拉角。
- 当前项目的 71 镜帧范围。
- “不做嘴型和手指”是该项目的用户约束，不是所有项目的通用默认值。

将实际项目的测量值当作案例，不要把它们硬编码进新任务。
